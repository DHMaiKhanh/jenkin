Từ zero đến vận hành Jenkins trong production

10 chặng, đi từ hiểu khái niệm CI/CD đến dựng pipeline tự động build – test – deploy, và vận hành Jenkins ổn định cho một team thật.

Tổng thời lượng ~10–14 tuần (học song song đi làm) Yêu cầu đầu vào biết dùng Git, đọc hiểu Linux cơ bản
Mỗi chặng nên có một sản phẩm cụ thể ở cuối — một job, một Jenkinsfile, một pipeline chạy được — chứ không chỉ đọc lý thuyết. Chặng 1–3 nên xong trong tuần đầu để có cảm giác "chạy được" sớm; các chặng nâng cao (7–10) có thể kéo dài hơn tùy vào việc bạn có sẵn hạ tầng (Docker/K8s) để thực hành hay không.
1

Nền tảng trước khi chạm vào Jenkins

3–5 ngày
  • CI/CD là gì, khác gì so với deploy thủ công — vẽ lại pipeline của một dự án bạn từng làm
  • Git ở mức thao tác pipeline cần: branch, tag, webhook, pull request
  • Linux cơ bản: quyền file, tiến trình nền, đọc log bằng tail -f, biến môi trường
  • Docker cơ bản: image, container, Dockerfile — vì hầu hết pipeline hiện đại đều build trong container
Mẹo: nếu đã quen Git và Docker rồi, bỏ qua chặng này — đừng học lại thứ đã biết chỉ vì nó nằm trong lộ trình.
2

Cài đặt và làm quen giao diện Jenkins

2–3 ngày
  • Cài Jenkins bằng Docker (docker run jenkins/jenkins:lts) thay vì cài trực tiếp lên máy
  • Tour qua Dashboard: Manage Jenkins, Build History, Console Output
  • Tạo thử một Freestyle Project chạy một script shell đơn giản
  • Hiểu khái niệm Job, Build, Executor, Workspace
3

Pipeline as Code — trái tim của Jenkins

1 tuần
  • Vì sao Declarative Pipeline nên là lựa chọn mặc định, Scripted chỉ dùng khi cần logic phức tạp
  • Cấu trúc Jenkinsfile: pipeline, agent, stages, steps, post
  • Biến môi trường, tham số hoá build (parameters), điều kiện chạy (when)
  • Viết Jenkinsfile đầu tiên cho một repo cá nhân, commit thẳng vào repo đó
Mẹo: luôn để Jenkinsfile sống trong repo của dự án, không viết pipeline trực tiếp trên UI — đó là khác biệt giữa "pipeline as code" và cấu hình thủ công khó tái tạo.
4

Kết nối với source control thật

3–4 ngày
  • Webhook từ GitHub/GitLab để trigger build tự động khi push
  • Multibranch Pipeline — mỗi branch tự có pipeline riêng, tự dọn khi branch bị xoá
  • Trigger theo Pull Request, build trạng thái hiển thị ngược lại trên GitHub
5

Build và test tự động cho thật

1 tuần
  • Tích hợp công cụ build của stack bạn dùng: Maven/Gradle, npm/yarn, pip, hoặc go build
  • Publish kết quả unit test (junit step) để Jenkins hiển thị pass/fail trực quan
  • Báo cáo code coverage (JaCoCo, Istanbul...) và archive artifact sau build
  • Đánh dấu build UNSTABLE khi test fail thay vì để im lặng trôi qua
6

Plugin và quản lý credentials an toàn

2–3 ngày
  • Cách chọn plugin: ưu tiên plugin chính thức, kiểm tra ngày cập nhật gần nhất trước khi cài
  • Credentials Store: lưu SSH key, token, mật khẩu — không bao giờ hardcode trong Jenkinsfile
  • Inject credentials vào pipeline bằng withCredentials
Mẹo: đây là chặng dễ bị bỏ qua nhất — nhưng lộ credentials trong log build là lỗi bảo mật phổ biến nhất ở người mới dùng Jenkins.
7

Docker bên trong pipeline

1 tuần
  • Build Docker image ngay trong stage của Jenkinsfile (docker.build)
  • Đẩy image lên registry: Docker Hub, GitHub Container Registry, hoặc registry nội bộ
  • Dùng agent { docker { image ... } } để mỗi stage chạy trong container riêng, môi trường build sạch và nhất quán
8

Continuous Deployment — đưa code ra production

1–2 tuần
  • Deploy lên server qua SSH, hoặc lên Kubernetes qua kubectl/Helm trong stage riêng
  • Chiến lược triển khai: rolling update, blue-green, canary — chọn theo mức chịu rủi ro của hệ thống
  • Cơ chế rollback khi deploy thất bại, và approval thủ công (input step) trước khi deploy production
Mẹo: luôn tách rõ pipeline CI (build/test) khỏi pipeline CD (deploy) — gộp chung khiến việc debug khi deploy lỗi trở nên rối.
9

Vận hành Jenkins ở quy mô team

1–2 tuần
  • Shared Libraries — dùng chung logic pipeline giữa nhiều repo, tránh copy-paste Jenkinsfile
  • Kiến trúc Controller–Agent (Master–Slave cũ): phân tán build ra nhiều node, scale theo tải
  • Phân quyền RBAC — ai được thấy job nào, ai được deploy lên production
10

Giám sát, backup và best practices dài hạn

liên tục
  • Backup JENKINS_HOME định kỳ, có kế hoạch khôi phục đã thử qua ít nhất một lần
  • Theo dõi sức khoẻ hệ thống: số executor đang bận, thời gian chờ trong queue, dung lượng đĩa
  • Dọn dẹp build cũ tự động (discardOldBuilds), review lại plugin không dùng định kỳ
  • Đọc release note của Jenkins LTS trước mỗi lần nâng cấp — tránh nâng cấp mù

Khi hoàn thành lộ trình này

Bạn sẽ có thể tự dựng một pipeline CI/CD hoàn chỉnh cho một dự án thật — từ commit đến chạy trên production — và đủ hiểu Jenkins để vận hành, debug, và mở rộng nó cho một team, không chỉ chạy demo cá nhân.
