Managing Jenkins

Mục tiêu giai đoạn: làm chủ vai trò quản trị viên Jenkins — cấu hình hệ thống, quản lý plugin, cài đặt công cụ toàn cục, thêm agent build, và dùng Script Console/CLI để thao tác nâng cao một cách an toàn.Stage goal: master the Jenkins administrator role — system configuration, plugin management, global tool setup, adding build agents, and safely using the Script Console/CLI for advanced operations.

Bài 5.1

Cấu hình hệ thống (System Configuration)

🎯 Mục tiêuHiểu trang Manage Jenkins → System, các thiết lập cốt lõi (số executor, JENKINS_HOME, biến môi trường toàn cục, System Message, Quiet Period) và khi nào nên chỉnh chúng.

Manage Jenkins → System nằm ở đâu

Vào Manage Jenkins (biểu tượng bánh răng) → System (hoặc URL /manage/configure). Đây là trang cấu hình lớn nhất, chứa hầu hết thiết lập toàn instance — khác với Configure Global Security hay Plugins là các trang riêng.

URLhttp://jenkins-host:8080/manage/configure

Số lượng executor (# of executors)

Executor là "slot" cho phép controller (hoặc agent) chạy song song bao nhiêu build. Controller mặc định có 2 executor — trong thực tế nên giảm về 0 trên controller và để toàn bộ build chạy trên agent, giữ controller chỉ lo điều phối.

Thiết lậpÝ nghĩaKhuyến nghị
# of executorsSố build đồng thời controller/agent có thể chạyController: 0, Agent: theo số CPU
LabelsNhãn để pipeline chọn agent (agent { label 'linux' })Đặt tên rõ ràng theo môi trường
Usage"Use this node as much as possible" hoặc "Only build jobs with matching label"Chọn vế 2 cho controller
🤔 Vì sao nên đưa executor về 0 trên controller?Chạy build trực tiếp trên controller khiến job có toàn quyền truy cập JENKINS_HOME, credentials, và tiến trình Jenkins — rủi ro bảo mật và ổn định. Tách build ra agent giúp cô lập lỗi và cho phép scale ngang.

JENKINS_HOME & biến môi trường toàn cục

JENKINS_HOME là thư mục gốc lưu toàn bộ cấu hình, job, build history, plugin. Backup thư mục này = backup toàn bộ Jenkins.

JENKINS_HOME (mặc định)~/.jenkins/                 # Linux, cài thủ công
/var/lib/jenkins/          # Linux, gói .deb/.rpm
C:\ProgramData\Jenkins\.jenkins  # Windows service

Trong Manage Jenkins → System, mục Global properties → Environment variables cho phép khai báo biến môi trường áp dụng cho mọi job/pipeline trên toàn instance.

Global properties# Tick "Environment variables" rồi thêm cặp Name/Value
Name:  MAVEN_OPTS
Value: -Xmx1024m

System Message & Quiet Period

System Message hiển thị banner thông báo cho mọi người dùng (VD: "Bảo trì 22h tối nay"). Quiet Period là số giây Jenkins chờ trước khi thực sự bắt đầu build sau khi bị trigger, giúp gộp các trigger liên tiếp (nhiều commit dồn dập) thành một lần build.

SystemSystem Message: "⚠ Bảo trì lúc 22:00, các job sẽ tạm dừng."
Quiet Period:  5  # giây, mặc định
💡 MẹoĐặt Quiet Period cao hơn (VD 30-60s) trên các repo hay bị nhiều commit dồn dập trong vài giây, để tránh build lãng phí cho từng commit riêng lẻ.
⚠️ Thận trọngThay đổi ở trang System ảnh hưởng toàn bộ instance, không phải một job. Luôn ghi chú lại thay đổi (đổi tên thư mục config trong Git nếu dùng JCasC) trước khi sửa trên production.
✍️ Thực hànhVào Manage Jenkins → System, đặt # of executors của controller về 0, thêm một biến môi trường toàn cục DEPLOY_ENV=staging, rồi kiểm tra biến này xuất hiện trong log của một pipeline đơn giản (sh 'echo $DEPLOY_ENV').

Lesson 5.1

System Configuration

🎯 GoalUnderstand the Manage Jenkins → System page, core settings (number of executors, JENKINS_HOME, global environment variables, System Message, Quiet Period), and when to touch them.

Where Manage Jenkins → System lives

Go to Manage Jenkins (gear icon) → System (or URL /manage/configure). This is the largest configuration page, holding most instance-wide settings — distinct from Configure Global Security or Plugins, which are separate pages.

URLhttp://jenkins-host:8080/manage/configure

Number of executors

An executor is a "slot" allowing the controller (or an agent) to run a certain number of builds in parallel. The controller defaults to 2 executors — in practice you should lower this to 0 on the controller and let all builds run on agents, keeping the controller focused on orchestration.

SettingMeaningRecommendation
# of executorsConcurrent builds a controller/agent can runController: 0, Agent: per CPU count
LabelsTags used by pipelines to pick an agent (agent { label 'linux' })Name clearly by environment
Usage"Use this node as much as possible" or "Only build jobs with matching label"Pick option 2 for the controller
🤔 Why set executors to 0 on the controller?Running builds directly on the controller gives job code full access to JENKINS_HOME, credentials, and the Jenkins process — a security and stability risk. Offloading builds to agents isolates failures and enables horizontal scaling.

JENKINS_HOME & global environment variables

JENKINS_HOME is the root directory storing all configuration, jobs, build history, and plugins. Backing up this directory backs up the whole Jenkins instance.

JENKINS_HOME (defaults)~/.jenkins/                 # Linux, manual install
/var/lib/jenkins/          # Linux, .deb/.rpm package
C:\ProgramData\Jenkins\.jenkins  # Windows service

On Manage Jenkins → System, the Global properties → Environment variables section lets you declare environment variables applied to every job/pipeline on the instance.

Global properties# Check "Environment variables" then add Name/Value pairs
Name:  MAVEN_OPTS
Value: -Xmx1024m

System Message & Quiet Period

System Message shows a banner to every user (e.g. "Maintenance tonight at 10 PM"). Quiet Period is the number of seconds Jenkins waits before actually starting a build after being triggered, coalescing rapid successive triggers (e.g. bursty commits) into a single build.

SystemSystem Message: "⚠ Maintenance at 22:00, jobs will pause."
Quiet Period:  5  # seconds, default
💡 TipSet a higher Quiet Period (e.g. 30-60s) on repos prone to bursty commits, to avoid wasteful builds for each individual commit.
⚠️ CautionChanges on the System page affect the entire instance, not a single job. Always note down changes (or version the JCasC config in Git) before editing production.
✍️ ExerciseGo to Manage Jenkins → System, set the controller's # of executors to 0, add a global environment variable DEPLOY_ENV=staging, then verify it shows up in a simple pipeline's log (sh 'echo $DEPLOY_ENV').

Quản lý Plugin (Plugin Management)

🎯 Mục tiêuBiết dùng Update Center để cài/cập nhật/gỡ plugin, hiểu dependency giữa các plugin, khi nào cần restart, cách ghim (pin) phiên bản, và nhận diện cảnh báo bảo mật plugin lỗi thời.

Update Center

Manage Jenkins → Plugins mở Update Center với 4 tab chính: Updates (bản cập nhật có sẵn), Available plugins (cài mới), Installed plugins (đã cài), Advanced settings (proxy, upload .hpi thủ công).

URL/manage/pluginManager/
TabChức năng
Available pluginsTìm và tick chọn plugin mới, bấm "Install without restart" hoặc "Download now and install after restart"
UpdatesLiệt kê plugin có bản mới hơn phiên bản đang cài
Installed pluginsUncheck để vô hiệu hóa, hoặc bấm Uninstall để gỡ hẳn

Dependency & restart

Nhiều plugin phụ thuộc lẫn nhau (VD: Pipeline plugin phụ thuộc Structs, Workflow-step-api...). Update Center tự động chọn kèm plugin phụ thuộc khi bạn cài. Một số thay đổi (đặc biệt plugin core hoặc thay đổi lớn) yêu cầu restart Jenkins mới có hiệu lực đầy đủ.

terminal (restart an toàn)# Restart khi không có build đang chạy
curl -X POST http://jenkins:8080/safeRestart --user admin:token
🤔 Vì sao có "Install without restart" và "…after restart"?Nhiều plugin (đặc biệt loại UI/Pipeline step) có thể nạp động (dynamic classloading) — không cần restart. Plugin đụng tới core hoặc security thường cần restart để đảm bảo trạng thái nhất quán.

Ghim phiên bản plugin (pin)

Trong Advanced settings, có thể tải file .hpi/.jpi cụ thể để cài đúng phiên bản mong muốn thay vì bản mới nhất — hữu ích khi cần giữ ổn định trước khi test bản nâng cấp.

terminal — cài plugin bằng CLIjava -jar jenkins-cli.jar -s http://localhost:8080/ \
  install-plugin git@5.2.1 -restart
⚠️ Cảnh báo bảo mật plugin lỗi thờiTrang Plugins hiển thị biểu tượng ⚠ cạnh plugin có lỗ hổng bảo mật đã công bố (tham chiếu security advisories của Jenkins). Không nên trì hoãn cập nhật các plugin này, đặc biệt plugin liên quan credentials, script security, hoặc SCM.
💡 MẹoTrước khi cập nhật hàng loạt plugin trên production, thử trên một instance staging có snapshot JENKINS_HOME giống hệt để phát hiện breaking change.
✍️ Thực hànhVào Manage Jenkins → Plugins → Available plugins, cài plugin Slack Notification, quan sát các plugin phụ thuộc được tự động chọn kèm, sau đó thực hiện safe restart.

Lesson 5.2

Plugin Management

🎯 GoalLearn to use the Update Center to install/update/uninstall plugins, understand plugin dependencies, when a restart is needed, how to pin a version, and how to spot security warnings for outdated plugins.

The Update Center

Manage Jenkins → Plugins opens the Update Center with 4 main tabs: Updates (available updates), Available plugins (install new), Installed plugins (already installed), Advanced settings (proxy, manual .hpi upload).

URL/manage/pluginManager/
TabFunction
Available pluginsSearch and check new plugins, click "Install without restart" or "Download now and install after restart"
UpdatesLists plugins with a newer version than currently installed
Installed pluginsUncheck to disable, or click Uninstall to remove entirely

Dependencies & restarting

Many plugins depend on each other (e.g. the Pipeline plugin depends on Structs, Workflow-step-api...). The Update Center automatically selects dependent plugins when you install one. Some changes (especially core plugins or major changes) require restarting Jenkins to take full effect.

terminal (safe restart)# Restart when no builds are currently running
curl -X POST http://jenkins:8080/safeRestart --user admin:token
🤔 Why "Install without restart" vs "…after restart"?Many plugins (especially UI/Pipeline step ones) support dynamic classloading — no restart needed. Plugins touching core or security typically need a restart to guarantee consistent state.

Pinning a plugin version

In Advanced settings, you can upload a specific .hpi/.jpi file to install an exact desired version instead of the latest — useful to stay stable before testing an upgrade.

terminal — install plugin via CLIjava -jar jenkins-cli.jar -s http://localhost:8080/ \
  install-plugin git@5.2.1 -restart
⚠️ Outdated-plugin security warningsThe Plugins page shows a ⚠ icon next to plugins with a published security vulnerability (referencing Jenkins security advisories). Don't delay updating these, especially plugins related to credentials, script security, or SCM.
💡 TipBefore bulk-updating plugins in production, test on a staging instance with an identical JENKINS_HOME snapshot to catch breaking changes.
✍️ ExerciseGo to Manage Jenkins → Plugins → Available plugins, install the Slack Notification plugin, observe which dependent plugins get auto-selected, then perform a safe restart.

  4. Install an exact plugin version via CLI.

Cấu hình công cụ toàn cục (Global Tool Configuration)

🎯 Mục tiêuCấu hình auto-installer cho JDK, Git, Maven, Gradle, NodeJS trong Manage Jenkins → Tools, và biết cách tham chiếu tool bằng tên trong khối tools {} của Jenkinsfile.

Manage Jenkins → Tools

Trang này (URL /manage/configureTools/) cho phép khai báo nhiều phiên bản của cùng một công cụ, mỗi phiên bản có một tên định danh (Name) duy nhất mà Jenkinsfile sẽ tham chiếu tới — Jenkins tự tải và cài đặt (auto-install) khi build cần.

Công cụPlugin cầnVí dụ Name
JDKtích hợp sẵn (core)jdk17
GitGit pluginDefault
MavenMaven Integrationmaven-3.9
GradleGradle plugingradle-8
NodeJSNodeJS pluginnode20

Auto-installer

Với mỗi tool, tick Install automatically rồi chọn nguồn tải (VD: Adoptium cho JDK, Apache cho Maven, nodejs.org cho NodeJS). Jenkins tải về agent lần đầu cần dùng và cache lại cho lần sau.

Manage Jenkins → ToolsJDK installations
  Name: jdk17
  ☑ Install automatically
    Add Installer → Install from adoptium.net → Version: jdk-17.0.10+7

Maven installations
  Name: maven-3.9
  ☑ Install automatically
    Add Installer → Install from Apache → Version: 3.9.6

Dùng trong Jenkinsfile qua khối tools {}

Jenkinsfilepipeline {
  agent any
  tools {
    jdk    'jdk17'
    maven  'maven-3.9'
    nodejs 'node20'
  }
  stages {
    stage('Build') {
      steps {
        sh 'java -version'
        sh 'mvn -v'
        sh 'node -v'
      }
    }
  }
}
🤔 Vì sao dùng tên tool thay vì cài cứng đường dẫn?Tham chiếu bằng tên logic giúp Jenkinsfile portable — cùng pipeline chạy được trên agent Windows/Linux khác nhau miễn có tool cùng tên được cấu hình, không cần sửa path tuyệt đối.
⚠️ Lưu ýtools {} chỉ hoạt động với agent có kết nối mạng để tải tool lần đầu; agent air-gapped cần cài thủ công và khai báo installation trỏ tới path có sẵn (bỏ tick "Install automatically").
✍️ Thực hànhKhai báo một Maven installation tên maven-3.9 với auto-installer từ Apache, rồi viết Jenkinsfile dùng tools { maven 'maven-3.9' } và chạy mvn -v để xác nhận.

Auto-installer

For each tool, check Install automatically then choose a download source (e.g. Adoptium for JDK, Apache for Maven, nodejs.org for NodeJS). Jenkins downloads it to the agent the first time it's needed and caches it afterwards.

Script Console — xóa build cũ hơn 30 ngàyimport jenkins.model.Jenkins

def cutoff = System.currentTimeMillis() - (30 * 24 * 60 * 60 * 1000)

  job.getBuilds().each { build ->
    if (build.getTimeInMillis() < cutoff) {
      println "Deleting ${job.name} #${build.number}"
      build.delete()
    }
  }
}

Chỉ cấp quyền RUN_SCRIPTS cho admin tin cậy tuyệt đối, và luôn thử trên println/dry-run trước khi gọi hành động ghi/xóa thật.

Script Console & CLI Basics

🎯 GoalUse the Groovy Script Console for admin tasks (e.g. bulk-deleting old builds), understand its risks, and get familiar with basic Jenkins CLI commands like list-jobs and build.

What is the Script Console

Manage Jenkins → Script Console (URL /manage/script) lets you run Groovy code directly inside the Jenkins process, with full access to internal APIs (Jenkins.instance, every job, every node). Extremely powerful for bulk tasks with no dedicated UI.

Script Console — delete builds older than 30 daysimport jenkins.model.Jenkins

def cutoff = System.currentTimeMillis() - (30 * 24 * 60 * 60 * 1000)

Jenkins.instance.getAllItems(hudson.model.Job.class).each { job ->
  job.getBuilds().each { build ->
    if (build.getTimeInMillis() < cutoff) {
      println "Deleting ${job.name} #${build.number}"
      build.delete()
    }
  }
}
⚠️ Extreme cautionThe Script Console runs with SYSTEM privileges, able to read/write/delete anything on the controller — including files outside Jenkins via Groovy I/O. There is no "undo". Only grant RUN_SCRIPTS to fully trusted admins, and always test with println/dry-run before invoking real write/delete actions.

Jenkins CLI

Download jenkins-cli.jar from the instance itself (/jnlpJars/jenkins-cli.jar) to run admin commands from a terminal, replacing UI clicks and making it easy to script from other CI/CD tools or cron.

🤔 Why use the CLI instead of clicking around the UI?The CLI enables automating repetitive admin tasks (cleaning up old jobs, bulk triggering, backups) in shell scripts/cron without opening a browser.
